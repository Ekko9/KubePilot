# KubePilot DevOps v1.0.0 功能详细说明

本文用于产品验收、运维交接和使用培训。平台菜单按照“资源监控 → 资源管理 → 镜像构建 → 发布管理 → 告警/通知 → 人员与审计”的工作流组织。平台支持 MySQL 5.7.22+ 和 MySQL 8.0。

## 1. 登录与总览

- 本地账号密码登录，密码仅以哈希形式存储，登录后签发有有效期的访问令牌。
- 管理员创建的新用户首次登录时必须修改初始密码；完成改密前，后端会拒绝访问其他业务接口，不能绕过页面直接操作。
- 创建用户、管理员重置密码和首次登录改密统一执行强密码校验：至少 8 位，并同时包含大写字母、小写字母、数字和特殊字符，空格不算特殊字符；前端即时提示，后端负责最终校验。
- 用户使用用户名登录；平台独立维护中文名/显示名，页面、操作人、值班信息和日志审计优先显示中文名，同时保留登录用户名用于追溯。
- 用户退出后，页面会清除令牌、用户名和密码输入内容，不在登录框保留上一个账号。
- 管理员可创建、启用、禁用和删除人员账号。
- 首次管理员由 Helm `security.adminUsername/adminPassword` 初始化，上线后应更换初始密码。
- 总览汇总命名空间、节点、Pod、Deployment、近期异常、发布和构建状态。
- `/healthz` 检查进程存活，`/readyz` 检查数据库和 Kubernetes API 依赖。

## 2. 资源监控

### Pod 监控

- 按命名空间查看 Pod、节点、阶段、就绪情况、重启次数和创建时间。
- 集群提供 Metrics API 时展示 Pod/容器 CPU、内存用量。
- 列表支持分页和状态识别，便于定位 Pending、Failed、Unknown。
- Job 正常完成的 Succeeded/Completed Pod 不被判定为“非 Running”故障。

### 服务器监控

- 以 Kubernetes Node 为服务器对象展示节点健康状态。
- 节点 DaemonSet 读取宿主机 `/proc` 采集 CPU 和内存，不依赖 metrics-server。
- 采集指定挂载目录的磁盘总量、已用量和使用率。
- 使用人员可维护路径，如 `/`、`/data`、`/var/lib/containerd`。
- DaemonSet 容忍节点污点以提高覆盖率，实际调度仍受集群策略约束。

## 3. 资源管理

### 支持资源

Pod、Deployment、StatefulSet、DaemonSet、Service、Ingress、ConfigMap、Secret、PersistentVolumeClaim、Job、CronJob。先选择命名空间，再按类型列出资源；界面以易读资源名显示，不重复展示 `.apps/v1` 等冗余文本。

### YAML 查看与编辑

- 普通用户可进入资源管理并查看常规资源列表、YAML、版本历史、版本差异和 Pod 日志，但不能保存或回退配置；包含敏感数据的 Secret 仅管理员可查看。
- 管理员可在只读能力之外编辑、保存和回退资源配置；后端写接口会再次校验管理员权限。
- 查看 Kubernetes 服务端返回的当前 YAML。
- 编辑器支持大内容滚动和日志/内容区域放大。
- 保存时校验 `apiVersion`、`kind`、名称和 namespace。
- Secret 数据敏感，只有授权管理员才应查看和修改。

### 版本、差异与回退

- 每次保存前记录当前清单，形成平台资源版本。
- 可比较当前内容与上一版本的 YAML 差异。
- 可选择历史版本回退，回退也写入审计记录。
- 平台资源版本与 Deployment rollout Revision 不同：前者是 YAML 历史，后者用于发布回滚。

### Pod 日志

- 仅 Pod 行提供日志入口，其他资源不显示该按钮。
- 日志工作台参考 Headlamp，支持业务容器、init container 和 ephemeral container 切换，以及有重启记录时查看上一实例日志。
- 支持 100～5000 行或全部日志、时间范围、时间戳、2 秒实时跟随、强制刷新、文本筛选、清屏后仅看新日志、自动滚动、自动换行、下载和独立日志区域放大。
- 关闭弹窗或暂停实时跟随后会停止轮询，避免后台持续请求 Kubernetes API。
- Pod 监控和资源管理中的 Pod 均提供重启操作。平台采用优雅删除并交由所属控制器重建；没有控制器的独立 Pod 和已完成 Job Pod 会拒绝操作，避免误删。

### 配置版本对比

- 资源编辑器保存前可将当前编辑内容与上一个历史版本比较。
- 对比界面采用类似 IDEA 的左右双栏：左侧历史版本、右侧当前编辑内容，行号对齐，并用红色、绿色区分删除和新增。
- 平台保存和回退后继续记录版本，可再次比较或回退。

### 时间显示

- 数据库时间统一按 UTC 保存，页面会将无时区的历史 UTC 时间按平台配置时区转换后显示。
- Helm 的 `app.displayTimezone` 同时设置应用展示时区和容器 `TZ`，默认 `Asia/Shanghai`，用于审计、告警、通知、发布、构建、Pod 日志、值班日程和资源版本时间。

## 4. 镜像构建

镜像构建分为“构建配置”和“执行历史”。

### 构建配置

可保存名称、说明、启用状态、Git URL/ref、构建目录、Dockerfile、目标镜像、构建参数、超时、并发策略、历史保留数和认证信息。

- HTTP/HTTPS Git 支持账号密码；SSH Git 支持 SSH Secret。
- 界面填写的 Git/Harbor 凭据经平台加密后保存，运行时生成或更新平台管理 Secret。
- Harbor 推送凭据与平台自身镜像拉取所用 `imagePullSecrets` 不同。
- `Git ref` 可为分支、Tag 或可检出的提交引用。
- `ARG` 是构建参数，不是容器运行时环境变量。
- 目标镜像须含 Registry、项目、镜像名和 Tag。

路径示例：仓库中 Dockerfile 为 `repo/devops/Dockerfile`。

- 若 Dockerfile 只需 `devops` 下内容：构建目录 `devops`，Dockerfile `Dockerfile`。
- 若需复制仓库其他目录：构建目录 `.`，Dockerfile `devops/Dockerfile`。
- Dockerfile 的 `COPY`/`ADD` 不能访问构建目录之外的文件。

### 执行过程

1. 验证配置启用状态、并发限制和请求参数。
2. 在构建 namespace 创建独立 Kubernetes Job。
3. init container 克隆 Git 到 Job 临时卷。
4. Kaniko 读取上下文和 Dockerfile，执行分层构建。
5. 使用 Registry 凭据推送镜像并尽可能利用远端缓存。
6. 平台持续读取 Job/Pod 状态和日志，更新执行历史。
7. 达到保留上限或手工删除历史时，同步清理关联 Job/Pod。

每次构建都会创建新 Pod，本地文件不跨构建保留。合理分层并启用 Kaniko 缓存可避免每次完整下载依赖。

### 日志和历史

- 实时刷新日志，支持滚动与日志区域放大。
- 展示配置、目标镜像、状态、开始/结束时间和错误摘要。
- 删除历史时同步处理 Kubernetes 构建资源。
- 失败排查优先查看 clone init container、Kaniko 日志和 Job 事件。

## 5. 发布管理

发布管理分为“更新发布”和“发布历史”。

### 更新发布

- 按命名空间筛选 Deployment。
- 选择应用后读取当前容器和镜像。
- 镜像可关联平台成功构建记录，也可输入完整地址。
- 只修改选定容器镜像，不修改端口、资源、探针、环境变量或卷。
- 使用 Deployment RollingUpdate 执行升级。

### 实时状态和历史

- 持续查询 generation、replica 状态和 rollout 条件。
- 展示调度、拉取、启动、就绪及失败事件，可查看相关 Pod 日志。
- 超时或失败不会标为成功，错误保留在发布记录。
- 历史记录 namespace、应用、镜像、副本、Revision、状态、操作人和时间，支持分页筛选。

### 回滚

- 下拉框列出可回滚 Revision、镜像和创建时间，无需手填。
- 回滚后持续跟踪 rollout，在历史中标识回滚与实际镜像。
- Kubernetes 已清理的 ReplicaSet/Revision 无法再回滚。

### 扩缩容和重启

- 支持调整 Deployment 副本数。
- 通过更新 Pod template annotation 触发滚动重启。
- 操作均记录操作人和审计信息。

## 6. 告警管理

### 规则模板

- 每个模板独占一行，显示指标、比较符、阈值、持续时间、重复间隔和级别。
- 内置模板提供可直接套用的参考值，最终应按业务基线调整。
- 套用后保存为独立规则，修改模板不会隐式改变已有规则。

### 告警规则

- 支持新建、编辑、启用、禁用、删除及中文告警级别。
- 数值指标使用比较符和阈值；状态类指标使用专用逻辑。
- `duration_seconds` 要求异常持续一段时间再触发，过滤瞬时波动。
- `repeat_interval_minutes` 控制持续告警重复发送。
- Pod/工作负载规则可关联 namespace；节点 CPU、内存、磁盘不显示无意义的 namespace。
- Pod 非 Running 排除 Job 正常完成的 Succeeded/Completed Pod。
- 可直接关联多个渠道，也可通过订阅关联人员和渠道。

### 告警事件

- 作为告警管理独立子菜单展示规则、目标、当前值、触发/恢复/最近通知时间和状态。
- 支持确认、删除与分页。
- 相同规则和目标通过指纹聚合，避免每轮采集创建重复事件。
- 条件首次满足并持续到阈值时间后创建 firing 事件；持续异常按重复间隔再通知；恢复后更新为 resolved。
- 故障中心提供待处理、处理中、已解决筛选；可编辑负责人、状态和处理说明，并保留操作时间线和审计记录。
- 自动恢复会记录系统处理活动；手动解决后若监控条件仍异常，下一轮监控会重新创建活动事件。

## 7. 通知管理

### 通知模板

为邮件、飞书、钉钉、企业微信、电话网关分别创建模板。模板支持标题和正文，可使用 `{title}`、`{message}`、`{rule_name}`、`{severity}`、`{namespace}`、`{target}`、`{resource_kind}`、`{resource_name}`、`{value}`、`{operator}`、`{threshold}`、`{started_at}`、`{status}` 等变量。可套用内置模板后修改。列表保持摘要展示，点击“查看详情”后在独立弹窗中查看完整标题、正文、来源和创建信息。

### 通知渠道

- 新建渠道时选择类型匹配的通知模板。
- 邮件配置 SMTP、TLS/SSL、发件人、认证和收件人。
- 飞书、钉钉、企业微信配置机器人 Webhook 和签名/密钥。
- 电话配置企业网关 URL、认证和号码字段映射。
- 多个邮箱或手机号支持逗号、分号、换行分隔。
- 敏感配置加密存储，列表不回显密码或 Token。
- 支持编辑、启用/禁用、测试发送和删除。

### 通知记录

- 记录渠道、事件、内容、发送状态、错误和时间。
- 普通用户只读；管理员可单条删除或勾选后批量删除通知记录，删除行为会写入操作审计。
- 可核验持续告警是否按间隔重复发送。
- 单个渠道失败不会中断告警扫描，错误保留供排查。

## 8. 人员、订阅、值班、角色和权限

- 人员管理中文名、登录用户名、邮箱、手机号、角色和启用状态；角色分为测试、研发、运维、管理员，禁用后不能登录。
- 内置 `admin` 管理员为系统保护账号，可修改邮箱和密码，但不能被删除、停用或取消管理员权限。
- 告警订阅关联人员、可选规则和一个或多个渠道，可启停或删除。
- 普通用户可查看告警订阅、通知发送记录和值班日程，但不能新增、修改或删除。
- 管理员可新增、修改和删除告警订阅，包括订阅人员、规则、通知对象及启用状态。
- 值班日程采用月历视图，支持上月/本月/下月切换、按人员筛选、覆盖天数统计和当天班次详情；同一天人员较多时收起为“+N 人”，避免排班把页面撑乱。
- 跨日班次会同时出现在涉及的日期中；当天详情展示值班人员手机号并支持直接拨号，未维护手机号时明确提示。
- 管理员可在当天详情中新增、修改和删除值班安排，包括值班人员、开始/结束时间及备注。
- 每个角色有默认菜单权限，管理员可在“系统管理 → 权限管理”的树形菜单中展开父模块、联动勾选子菜单，为非管理员用户覆盖权限或恢复为角色默认。管理员固定拥有全部菜单权限。
- 权限管理入口、权限目录、其他用户权限读取和权限保存接口均仅管理员可访问；普通用户无法通过直接调用接口绕过页面限制。
- 登录响应和 `/api/me` 只返回当前用户自己的有效菜单，前端隐藏无权菜单，业务接口同时执行后端菜单权限校验。

## 9. 操作审计

- 记录用户名、动作、资源、详情和发生时间；不采集、不展示来源 IP。
- 覆盖登录成功、登录失败、退出、首次改密，以及资源更新/回退、发布、构建、规则、通知和人员等关键操作。
- “系统管理 → 日志审计”仅管理员可见；审计查询和删除接口也强制校验管理员权限。
- 管理员可删除单条、勾选后批量删除或清空日志；删除/批量删除/清空行为本身会生成一条新的审计记录，避免清理过程完全无痕。
- 敏感字段应脱敏，审计记录不能当作密钥保存位置。
- 强合规环境还应启用 Kubernetes API 审计与集中日志。

### 界面验收演示数据

- `scripts/seed_demo_data.py` 可重复创建值班日程、故障中心及通知记录的演示数据，所有内容均带 `[演示]` 标识。
- 脚本只删除和重建自身创建的 `demo:` / `[演示]` 数据，不修改真实故障、真实通知、人员或构建配置。
- 演示故障不关联告警规则，因此不会被后台指标采集自动恢复，可在故障中心手动流转状态来查看效果。

## 10. 权限和安全边界

- 平台依赖 Kubernetes ServiceAccount；生产可按实际功能裁剪 Chart RBAC。
- Kubernetes Secret 可编辑但必须限制查看和操作权限。
- Git、Harbor、SMTP、Webhook、电话凭据依赖 `encryptionKey`；恢复数据库时必须同时恢复密钥。
- 发布只更新镜像，业务配置统一在资源管理维护。
- 外部 MySQL、Harbor、Git 和通知网关的可用性与备份不由平台托管。

## 11. 推荐流程

### 新应用上线

1. 创建人员和必要凭据。
2. 创建构建配置，验证 Git、路径、Dockerfile 和 Harbor。
3. 执行构建并确认日志和目标镜像。
4. 用 Helm/GitOps/kubectl 创建首次业务资源。
5. 在资源管理核对端口、探针、环境变量和资源限制。
6. 发布新镜像，观察 rollout 和 Pod 日志。
7. 配置规则、模板、渠道、订阅并测试通知。

### 日常发布

1. 更新 Git ref 或目标 Tag并构建。
2. 确认镜像推送成功。
3. 选择 namespace、Deployment 和新镜像。
4. 开始升级并观察实时状态。
5. 在历史确认 Revision 和最终镜像。
6. 失败时从下拉框选择上一可用 Revision 回滚。

### 配置修改

1. 在资源管理打开资源并核对 namespace。
2. 修改 YAML，保存后查看差异。
3. 必要时回退上一个平台资源版本。
4. Deployment 配置变化后观察新 Pod 就绪状态。

### 告警闭环

1. 按节点/Pod 基线套用规则模板。
2. 设置持续时间和重复通知间隔。
3. 关联渠道或人员订阅。
4. 测试渠道，确认通知记录成功。
5. 演练触发、确认、重复通知和恢复。
6. 对误报调整范围、阈值或持续时间。

## 12. 验收清单

- 登录成功，页面和 `/healthz` 显示 `v1.0.0`，`/readyz` 正常。
- 命名空间、节点、Pod、Deployment 列表正常分页。
- 节点 CPU、内存、磁盘可见，挂载路径可维护。
- 支持资源可查看；测试对象可编辑、比较和回退。
- Pod 日志可选择容器、实时刷新和放大。
- 构建可拉取 Git、找到 Dockerfile、推送 Harbor并显示实时日志。
- 构建历史可删除且无孤儿 Job/Pod。
- Deployment 可滚动升级，历史包含镜像和 Revision。
- 回滚候选显示 Revision、镜像、时间，回滚状态正确。
- 规则模板、规则编辑/删除、事件删除正常。
- 五类通知渠道完成配置校验或测试。
- 持续告警按间隔产生多条通知记录，恢复后状态更新。
- 用户、订阅、值班和审计记录完整。
